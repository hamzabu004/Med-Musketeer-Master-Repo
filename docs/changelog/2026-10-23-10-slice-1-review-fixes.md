## What changed
A `/code-review` of `feat/cloud-stack-skeleton` reported 10 findings; each was checked against the code.
- **Fixed:**
  - All six shell scripts in the repository were committed without the executable bit (`core.fileMode` is off on the NTFS drive), so they failed on a fresh clone; now mode 755 in git.
  - The Postgres health check now connects over TCP, so it cannot pass during the entrypoint's socket-only init phase.
  - `/healthz` wraps every check in the configured timeout, and libpq's `connect_timeout` is rounded up (0 meant "wait forever").
  - The integration tests skip with a reason when no container engine is installed.
  - `run_cloud_tests.sh` and `init-env.sh` resolve relative paths against the caller's directory, and the evidence records the engine actually used.
  - ZITADEL reads the masterkey from the environment (`--masterkeyFromEnv`), so it no longer appears in the process list.
  - `requirements.lock` is generated by pip-compile with hashes (392, including aarch64 wheels) and installed with `--require-hashes`.
- **Deferred:** ZITADEL's API and Login UI run as root, as in ZITADEL's reference compose, to share the bootstrap PAT file. Recorded in `gaps.md`, to fix before the cloud is exposed beyond Tailscale.
- **Not a defect:** the reviewer suspected `opentelemetry-api` in the lock came from a polluted environment; it is a dependency of FastAPI.
