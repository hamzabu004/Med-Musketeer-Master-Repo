| # | Severity | File | Finding | Failure scenario | Outcome |
|---|---|---|---|---|---|
| 1 | High | `cloud/backend/app/dev_seed.py` | ZITADEL objects are created before the database transaction and never removed on failure; the empty-stack guard only looks at the database. | A weak `--password` fails at the first user after the org exists; a re-run passes the guard and fails with 409, until the ZITADEL volume is wiped. | **Fixed.** Every failure deletes what was created in ZITADEL (the organisation, which takes its users, and the system admin). `test_dev_seed`. |
| 2 | Medium | `cloud/backend/app/zitadel.py` (`profiles`) | An expired profile that ZITADEL no longer returns is still served, and nothing is evicted. | A deleted user's name is shown forever; the cache grows with every user ever looked up. | **Fixed.** Expired entries are evicted before each lookup. `test_an_expired_profile_zitadel_no_longer_returns_is_dropped`. |
| 3 | High (security) | `cloud/backend/app/zitadel_bootstrap.py` | `devMode` was on for the whole app if any origin used http. | `DASHBOARD_ORIGINS=http://localhost:3000,https://…vercel.app`: the production app relaxes redirect checks, so codes can reach whatever listens on localhost. | **Fixed.** Mixing http and https origins stops the bootstrap; dev mode only when all origins are http. The settings example no longer suggests mixing. `test_http_and_https_origins_cannot_share_the_app`. |
| 4 | Medium | `cloud/backend/app/zitadel_bootstrap.py` | Any 400 containing "change" was treated as "No changes". | A real validation error mentioning "change" is swallowed; sign-in later fails with a redirect mismatch. | **Fixed.** Only a message starting "No changes" is accepted. Test case added. |
| 5 | Medium | `cloud/compose.yaml`, `cloud/emqx/mm-entrypoint.sh` | `depends_on` is ignored on Docker's restarts (`unless-stopped`, host reboot), so the start-order fix did not hold there. | After a reboot of the cloud Pi, EMQX refuses every client for about 15 s. | **Fixed.** The entrypoint waits for the API's `/livez` (up to `MM_API_WAIT_S`, 120 s) before starting EMQX; compose keeps the ordering. |
| 6 | Low | `cloud/backend/app/zitadel_bootstrap.py` | An empty `MM_DASHBOARD_ORIGINS` leaves an existing app with its old redirect URIs. | Unreachable through compose, which defaults the value. | **Accepted.** Docstring now says an empty value leaves the app untouched. |
| 7 | Low | `cloud/backend/app/main.py` | Unhandled 500s carry no CORS header (Starlette's error middleware sits outside CORS). | The dashboard sees a network error rather than the 500. | **Accepted.** The dashboard (Phase 3) treats a network error as "server unavailable"; no clinical data depends on telling them apart. |
| 8 | Low | `cloud/backend/app/zitadel_bootstrap.py` | A second copy of the origin parsing. | CORS and redirect URIs could drift apart. | **Fixed.** Shared `parse_origins` in `app/settings.py`. |

| 10 | Low | `cloud/backend/app/dev_seed.py` | `PEOPLE` was mutated by `seed()`. | A second run in one process starts with the previous ids. | **Fixed.** `PEOPLE` is a tuple of templates; `seed()` works on copies. |
