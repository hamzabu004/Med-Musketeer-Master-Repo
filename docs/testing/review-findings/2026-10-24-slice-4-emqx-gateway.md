# Code review findings — Slice 4 (EMQX gateway listener, broker hooks, cloud certificate)

- **Reviewed:** uncommitted work on `feat/cloud-emqx-gateway`, `/code-review`, 2026-10-24
- **Status:** Open; none fixed yet.
- **Verified so far:** none; all as reported by the review.

| # | Severity | File | Finding | Failure scenario | Proposed fix |
|---|---|---|---|---|---|
| 1 | High | `cloud/backend/app/broker.py` (`authorise`) | Authorisation runs only on new PUBLISH/SUBSCRIBE; a suspended or revoked gateway keeps its existing subscriptions, and nothing disconnects it. | A suspended gateway subscribed to `mm/fixed/+/command` keeps receiving every wearable's commands for as long as its session lasts. | Disconnect the client through EMQX's REST API when a gateway is suspended or revoked (D4 "may"); EMQX API key from a bootstrap file rendered at start. |
| 2 | High | `cloud/backend/app/broker.py` (`authorise`) | Authorisation checks the device, not the credential, so revoking a certificate does nothing to a connected session; `cloud-backend.md` says it is refused "at once". | A compromised gateway key is revoked but the device stays active: the attacker's open session keeps publishing until it reconnects on its own. | Same disconnect on credential revoke; correct the decision text. |
| 3 | High | `cloud/emqx/emqx.conf.template`, `broker.py` (`gateway_refusal`) | The client id is not bound to the certificate. | Gateway B connects with gateway A's client id: EMQX takes over A's session (A kicked, B inherits a persistent session); repeated, A is kept offline. | `peer_cert_as_clientid = cn` on the gateway zone, or refuse when clientid ≠ username. |
| 4 | Medium (by design) | `cloud/backend/app/broker.py` (`gateway_may`) | Any gateway may publish for any wearable and subscribe to every wearable's commands, across organisations. | A compromised gateway forges alerts for another organisation's wearable and reads all commands. | Decided observe-only in D5 for this iteration; enforcing wearable↔gateway assignment is in `gaps.md`. Record the cross-organisation reach as a residual risk. |
| 5 | Medium | `tools/ca-tool/mmca/core/ca.py` (`issue_cloud`) | The archive step runs outside the try/rollback. | With `server.key` missing, `--replace` moves the certificate and metadata into history, fails on the key and leaves `cloud/` empty. | Move the archive into the try, or check all three files exist first. |
| 6 | Medium | `tools/ca-tool/mmca/core/ca.py` (`issue_cloud`, also `issue_device`) | Rollback leaves the empty `history/<serial>/` directory. | Every later `--replace` fails with FileExistsError until someone deletes it. | Remove the directory on rollback (and use a unique name if `serial` is missing). |
| 7 | Low (Slice 6) | `cloud/compose.yaml` | Publishing 8883 on the Tailscale address fails if Docker starts before Tailscale. | After a reboot of the cloud Pi, EMQX does not start until someone restarts the stack. | Order Docker after Tailscale (systemd), or bind 0.0.0.0 with a host firewall; decide in Slice 6. |
| 8 | Low | `tools/ca-tool/mmca/cli.py` | `issue cloud` asks for confirmation and the passphrase before checking whether a certificate exists. | The operator types the passphrase only to be told to use `--replace`. | Check existence first, as `issue_device` does. |
| 9 | Low | `tools/ca-tool/mmca/core/ca.py` | `issue_cloud` copies `issue_device`'s archive/write/rollback sequence. | Fixes to findings 5 and 6 must be made twice. | One shared helper. |
| 10 | Low | `cloud/backend/app/broker.py` (`gateway_refusal`) | Authentication accepts any UUID spelling, authorisation only the canonical form. | A gateway with an upper-case CN connects but every publish is denied silently. | Require the canonical form in authentication too. |
